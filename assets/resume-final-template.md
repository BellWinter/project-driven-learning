# 一页式简历项目经历模板

> 阶段 7 使用。把项目压缩成简历上的一段（3-5 行），直接可粘贴进简历。
> 格式：**项目名 + 技术栈 + STAR 一句话 + 量化结果**。

## 模板（直接填）

```
**项目名称**：`[云原生 CI/CD 自动化部署平台]`
**技术栈**：`[GitLab / Jenkins / Docker / Kubernetes / containerd]`
**项目描述**：
  独立设计并搭建了基于 GitLab + Jenkins + K8s 的自动化部署平台，实现"代码提交即自动构建部署"。
  负责环境搭建、CI/CD 流水线编写（Jenkinsfile 声明式流水线）、K8s 资源编排（Deployment/Service/
  ConfigMap/Secret/Ingress）及滚动更新与秒级回滚。
  独立排查并解决 24 个部署级问题，覆盖 SSRF 防护、CSRF 校验、containerd 2.x 配置等深水区。
**量化结果**：部署从手动 1 小时 → 全自动 5 分钟；回滚时间 < 10 秒；构建成功率 100%。
```

## 写作规则

1. **动词开头**：设计/搭建/编写/排查/优化，不要"负责"堆砌
2. **技术栈要具体**：写版本/组件名，别写"熟悉云原生"
3. **量化优先**：每个行动尽量配数字（处理数据量/节点数/时长/成功率）
4. **有深水区**：至少提 1 个有难度的排障点（SSRF/CSRF/版本差异），这是面试官追问的钩子
5. **长度控制**：项目描述 ≤ 3 行，量化结果单独一行

## STAR 四要素核对（写完后自查）

| 要素 | 含义 | 本项目对应 |
|---|---|---|
| **S** Situation | 背景：为什么要做这个项目 | |
| **T** Task | 目标：要解决什么问题 / 达到什么指标 | |
| **A** Action | 行动：我做了什么（动词开头，含技术决策） | |
| **R** Result | 结果：可量化的产出 | |

> 面试讲述顺序：先 R（30 秒内给出量化结果抓住注意力），再补 S/A 细节。

## 岗位定制角度

| 岗位 | 包装侧重 |
|---|---|
| 运维/DevOps 岗 | 排障能力、自动化、稳定性（监控/回滚/容灾） |
| 后端开发岗 | 架构设计、代码质量、部署效率 |
| 数据分析岗 | 数据量、分析结论、业务洞察 |
| 前端开发岗 | 交互实现、性能优化、工程化 |
