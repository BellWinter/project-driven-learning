# 学习成果验证（Learning Check）

> 阶段 6 使用。"项目跑通"≠"学会了"，本模板验证知识是否真正掌握。
> 通过标准：用户能独立讲清"项目架构 + 3 个以上核心概念 + 2 个以上排障故事"。

## 一、Mini-Test（3-5 题）

| # | 题型 | 题目 | 用户作答 | 批改（✓/✗ + 讲解） |
|---|---|---|---|---|
| 1 | 概念题 | [如：K8s 里 Deployment 和 StatefulSet 的区别？] | | |
| 2 | 概念题 | | | |
| 3 | 场景应用题 | [如：Pod 一直 Pending，你会怎么排查？] | | |
| 4 | 场景应用题 | | | |
| 5 | 排障题 | [如：从你的项目排障记录里挑一个，讲清现象/根因/方案] | | |

**判定**：答对 ≥ 80% → 通过；否则针对错题补充讲解 + 出 1-2 道同类题再测。

## 二、费曼讲解（用户用自己的话讲）

**任务**：请用户像给同事讲解一样，讲清楚以下内容（AI 记录并找漏洞）：
1. 项目整体架构（数据/请求怎么流动的）
2. 用到的 3 个核心概念（是什么、为什么用、怎么用的）
3. 踩过的 2 个坑（现象 → 根因 → 怎么修的）
4. 如果再重做一次，哪里会做得不一样

**AI 检查点**：
- [ ] 有没有讲不清/讲错的地方？→ 记录并补充讲解
- [ ] 有没有用"大概""好像"等模糊词？→ 追问确认

**判定**：能流畅讲清 80% 以上 → 通过 ✅；否则针对薄弱点补课。

## 三、最终结论

- [ ] Mini-Test 通过（得分：/）
- [ ] 费曼讲解通过
- [ ] 综合结论：**已掌握 / 基本掌握（薄弱点：）/ 未掌握（需补：）**
